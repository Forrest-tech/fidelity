# 阶段 F：验收方案（2026-11-23）

目标（需求 v2 Q-3、§9）：用足够多、能证明的题，测出"库 + AI 工具"回答正确率是否 ≥ 99%，陷阱题零容忍；
不靠负责人或开发者的记忆，也不靠同事。

## 四个专家问题

**1. 顶尖专家会做、但负责人没要求的事**
- 先确认"库本身能不能被找到"：AI 答错，往往不是识别错，而是找不到条款。所以先查结构
  （条款号、章节、版本号）是否正确——这一步已经发现并修好了 AS 3500.1/.2:2021 整本被标成"Front matter"、
  没有条款列表、`std_id` 写成 "AS NZS 3500.1-" 的问题，3500.3:2021 也因附录标题匹配失败一直没通过校验。
- 题目必须分层抽样（每本标准、每个 Section 都有），并单列陷阱题；答错时要区分是"库错"还是"AI 错"。
- 同一套题在修复前的库和修复后的库上各跑一次，证明修复有效，而不是只报一个分数。

**2. 从什么原始素材出发**
- 出版方的原生文字 PDF（不是我们蒸馏出来的 Markdown）：每个标准答案都必须逐字出现在原 PDF 那一页上。
- 现有 100 题 NCC 题库（其中 26 题已在 Grok 上实测通过）继续保留。
- NCC 2025 引用表：库里没有的版本（AS/NZS 3500.1–.4:2025）正好做"版本不在库中"的陷阱题。

**3. 具体方法和工具**
- 出题：AI（DeepSeek）读一页原文出题，答案必须是从该页逐字复制的数值；程序再到原 PDF 页面核对，
  对不上就丢弃。陷阱题由程序按规则生成（不存在的条款号、库里没有的版本、错误前提），不经 AI。
- 答题：按 Grok 说明包的规则作答，库内容用 BM25 检索后提供（与 Grok 实际"搜索 → 读文件"的方式一致）。
- 判分：确定性规则，不用 AI 当裁判——数值和单位必须对；引用的文件、页码（±1 页）必须对，
  并且引用的原文必须真的出现在原 PDF 那一页（引用自动回查）；陷阱题必须说"库中没有"，不能编数值。
- 统计：Wilson 95% 置信区间；0 错时 300 题才能说错误率上限约 1%。

**4. 除了负责人和开发者，谁能证明结果是对的**
- 原 PDF 本身（每个标准答案、每条引用都自动回查原页）。
- 两个不同的模型各答一遍，结果不一致的题自动标出来，进人工复核清单。
- 任何人从仓库拉代码、用同一题库重跑，得到同样的判分（判分是确定性的）。

## 方案评分

| 方案 | 分数 | 理由 |
|---|---|---|
| 机器出题 + 原 PDF 核对 + 自动答题 + 确定性判分 + 双模型对照 + 修复前后对比 | **9.5** | 标准答案不依赖任何人的记忆；判分可复现；能区分库错和 AI 错。不足：答题的不是 Grok 本身（Grok 没有 API 密钥），所以同一题库导出给负责人在 Grok 上抽测，用同一个判分器打分 |
| 开发者手写 300 题 | 7.0 | 出题人就是被测系统的作者，有偏差；写不快；答案靠记忆 |
| 用 AI 当裁判判分 | 6.5 | 裁判本身会错，而且两次判分可能不同，不可复现 |
