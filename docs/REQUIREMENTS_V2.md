## 0. 一句话目标

公司员工在 AI 工具里问一个管道/建筑规范问题，得到的答案**引用正确版本、正确条款、正确页码**；
系统不知道时说不知道。Fidelity 是保证这件事的"质检站"，不是一个格式转换器。

## 1. 先收窄范围（不做什么）

v1 列了 26 条功能，覆盖所有格式、所有存储、所有 AI 工具。v2 先把一条主线做到商业级：

| 现在做 | 推迟（等主线达标后按数据决定） |
|---|---|
| 标准/规范类 PDF（文字版 + 扫描版），来源 Dropbox | Word/Excel/PPT、邮件 `.msg`、网页快照、图纸、zip |
| 输出到 Dropbox 知识库，供 Grok 使用 | Google Drive、本地文件夹；Claude/Codex/Gemini 适配包 |
| 一个房间 = 一个源文件夹 → 一个输出文件夹 | 多源映射、定时同步 |
| 管理员、审核员两种角色 | 查看者、细粒度权限 |

**为什么**：现在暴露的问题（重复件、受保护件、版本混乱、网络中断、内存不足、路径大小写）都出在主线上。
主线不稳，加格式只会放大问题。

## 2. 铁律（不变，补充一条）

| ID | 规则 | 谁来证明 |
|---|---|---|
| IR-1 | 源文件夹只读 | 只读凭据 + 写入白名单 + 运行前后快照对比（已有），每次运行自动出报告 |
| IR-2 | 只有通过验证的内容才以"可信"发布 | 发布记录里每份文件都有验证结果和验证人 |
| IR-3 | 不绕过版权保护 | 受保护文件只记元数据；解锁版必须附授权证明 |
| IR-4 | 不编造 | 陷阱题零容忍（见 §6） |
| **IR-5（新）** | **合法使用**：标准文本的分发范围不超过公司持有的许可证；文本发给第三方 AI 服务前要有书面确认 | 许可证清单（每个标准对应购买记录/许可类型/用户数），由负责人或法务签字 |

> IR-5 是顶级专家第一件会问的事：Standards Australia 的 PDF 通常是按人/按机器授权，把全文放进
> 共享文件夹再交给 Grok（xAI）读取，可能超出许可。这件事不解决，系统做得再好也不能上线。

## 3. 数据模型：从"文件"升级到"标准的版本"

现在系统以**文件**为单位，所以同一份标准的扫描版、可搜索版、"已解锁"版、重复副本会互相打架。
专业做法是按图书馆学的 FRBR 模型分三层：

| 层 | 例子 | 系统里的含义 |
|---|---|---|
| 作品 Work | AS/NZS 3500.1 水供应 | 员工问问题时指的东西 |
| 版本 Edition | 2003 / 2015 / 2018 / 2021 版，修订单 Amdt 1、Amdt 2 | 每个版本有状态：现行 / 已被取代 / 草案 / 被 NCC 某版引用 |
| 文件 File | `AS-NZS_3500.1-2021 Printed.pdf`、`…Converted to Searchable.pdf` | 同一版本的多个副本，系统只选**最好的一份**蒸馏，其余标为"同版本的其他副本" |

| ID | 需求 | 谁来证明 |
|---|---|---|
| D-1 | **版本登记表**：每个标准版本记录编号、年份、修订单、现行状态、被哪版 NCC/哪个州引用、来源（官方目录链接） | 与 Standards Australia 官方目录和 NCC "Referenced Documents" 表逐条核对，差异清单为空 |
| D-2 | 同一版本多个文件时自动选最佳副本（文字版优先于扫描版，解锁版优先于受保护版），并说明原因 | 测试集：每类组合各一例 |
| D-3 | 修订单与基础版本关联；输出里标明"本条款已被 Amdt 2 修改" | 抽查 10 条被修订的条款，答案引用修订后内容 |
| D-4 | 已被取代的版本照样发布，但每个文件头写明"已被 XXXX 版取代，仅供查旧项目" | AI 陷阱题：问现行要求时不得引用旧版 |
| D-6 | **许可证水印**：读取每个标准 PDF 上供应商印的"Licensed to … / Accessed by …"，记入许可清单（只记录，不阻止发布，见 §12 负责人决定） | `app/distill/licence.py` + 测试；许可清单脚本可重跑 |
| D-7 | **CC BY 署名**：采用 CC BY 许可的内容（NCC 2022 起）每个文件写明出处和许可 | 抽查发布文件，署名行齐全 |
| D-5 | 识别重复用**内容指纹 + 版本身份**，不只用文件哈希（同一版本的扫描件和文字件哈希不同） | 现有 AS 3500 文件夹的 39 个文件分组结果由负责人确认一次，作为固定测试数据 |

## 4. 正确性：可量化、可复现、有统计意义

| ID | 需求 | 谁来证明 |
|---|---|---|
| Q-1 | 文字识别：字符错误率 CER ≤ 1%，数字 100% 正确 | **金标准页**：从真实源文件分层抽 200 页（文字版/扫描版/表格/公式），由人对照原页逐字校对两遍，两人不一致处第三人裁决；CER 用 `jiwer` 计算 |
| Q-2 | 表格结构正确 | 金标准表格 50 张，用 TEDS 指标评分 ≥ 0.95 |
| Q-3 | 问答正确率 ≥ 99%，并且**有统计意义** | 题量按统计算：0 错时至少 **300 题**才能以 95% 置信度说错误率 ≤ 1%（100 题全对只能说明 ≤ 3%）。陷阱题单列，零容忍 |
| Q-4 | 每次改动不倒退 | 金标准页 + 题库进 CI 回归；任何一项下降则 PR 不能合并 |
| Q-5 | 同一源文件 + 同一流水线版本 → 同一输出（字节级） | CI 里重复跑两次比较哈希 |

题目来源见 §7：优先用真实员工问题，不用开发者自己编的题。

## 5. 稳定可用：按商业服务的标准运维

| ID | 需求 | 谁来证明 |
|---|---|---|
| S-1 | **服务目标（SLO）**：网页可用率 ≥ 99.5%（工作时间）；一次运行因系统原因失败的比例 ≤ 1%；单页处理时间：文字版 ≤ 2 秒、扫描版 ≤ 30 秒（Mac mini） | 监控面板自动统计，每周一份报告 |
| S-2 | **网络故障容忍**：Dropbox 断线、超时、限流不让文件或运行失败；失败的文件下次自动重试 | 故障注入测试：用 Toxiproxy 模拟断线、慢速、SSL 中断，运行仍完成 |
| S-3 | **资源保护**：按剩余内存、磁盘决定并发；内存不够时排队而不是互相拖慢 | 在 4 GB 和 32 GB 两种配置上压力测试，记录每页耗时不劣化 |
| S-4 | **任务系统**用成熟组件（如 Procrastinate/Dramatiq/Celery），不再自写进程监管 | 重启服务器、杀进程、断电恢复三种演练，任务不丢不重 |
| S-5 | **可观测**：结构化日志、指标（Prometheus）、错误追踪（Sentry 自托管或 GlitchTip）、告警发到负责人邮箱/手机 | 每类故障演练一次，告警在 5 分钟内送达 |
| S-6 | **备份与恢复**：数据库、审计记录、配置每日备份（restic），每月做一次恢复演练 | 演练记录 |
| S-7 | **测试环境与发布**：生产/测试两套环境；版本号；发布前在测试环境跑完整回归；一键回滚 | 每次发布有发布单（版本、变更、测试结果、回滚方式） |
| S-8 | 生产不跑在 4 GB 开发机上 | Mac mini 到货后迁移，开发机只做开发 |

## 9. 除了开发者和负责人，谁能证明结果是对的

1. **源文件本身**：每个答案都能回到原 PDF 的那一页，自动比对引用文本与原页渲染文字。
2. **独立的机器核对**：每个答案的引用回到原 PDF 那一页自动比对；同一题让不同的 AI 工具各答一次，答案不一致的题自动标出（不依赖外部人员）。
3. **独立的机器**：两个不同识别引擎一致才算可信（已有）；同一题让 Grok 与 Claude 分别回答，不一致的题自动进人工复核。
4. **官方权威来源**：版本状态与 Standards Australia 目录、NCC 引用表对得上。
5. **统计**：足够题量和置信区间，而不是"跑了几题都对"。
6. **真实使用**：上线后员工的纠错报告，确认的错误数随时间下降；每条确认错误进回归题库。
7. **可复现**：任何人从仓库拉代码，用脚本可以重跑全部评估得到同样分数。
8. **外部审查**：许可证由供应商或法务确认；安全由第三方做一次渗透测试（上线前）。

## 12. 阶段 A 发现（2026-11-22）

详见 `docs/licence/INVENTORY.md`。要点：

1. **AS 3500 文件夹里 39 份文件，没有一份是公司自己的许可。** 供应商水印显示，它们分别授权给：
   - 另一家工程公司（Norman Disney & Young）；
   - TAFE NSW；
   - 一位标准委员会成员（"仅供委员会使用"）；
   - 一位个人（"仅限个人使用，禁止存储、分发或在网络上使用"）。
2. **Standards Australia 现行条款**：禁止把内容存放在网络或文件共享平台上；未经书面同意，禁止提供给任何 AI 系统。
3. **已发布 29 份**到 Grok 读取的 `/Transfer_Md/AS 3500`，而且文件里带着被许可个人的姓名。
4. **NCC 2022 起采用 CC BY 4.0**，官方明确允许用于 AI，只需署名。

**对范围的影响（建议）**：知识库的第一批内容改为 NCC（合法、免费、允许 AI 使用）。AS 标准要等公司取得许可和 AI 使用的书面同意之后再处理。在此之前，AS 3500 房间只用于开发测试，结果不发布到 Grok 读取的文件夹。

**IR-3 补充（建议）**：别人去掉保护后的副本（"-已解锁"）视同绕过保护，不使用。

**负责人决定（2026-11-22）**：公司已有授权，其中很多内容本身就是公开允许使用的。因此：
- AS 3500 保留发布和使用；
- 以后所有类似文件都同样处理，许可水印只记入清单，不阻止蒸馏和发布。

IR-5 的证明就是负责人的这次确认。上面"对范围的影响"和"IR-3 补充"两条建议不再执行。

## 13. 阶段 B 进展（2026-11-22）

已实现 `backend/app/distill/editions.py`（D-1 至 D-5 的第一版）：

- **识别版本**：先看文件自己的标题页，再看文件名，最后看所在文件夹。实例：放在 2018 文件夹里的 "AS 3500.0 Glossary" 按标题页是 2003 版。
- **最佳副本**：同一版本有多份时，只发布最好的一份，其余在房间里显示为"已跳过 · 同版本已用"，不再要求审核。
- **现行/旧版**：只在本库范围内判断，不代表出版方目录。旧版发布时文件头写明 `edition_status: superseded` 和 `superseded_by`，正文顶部加一行提示。
- **"更新版本标注"**：重新上传已发布的文件，刷新上面这些标注；保留原来的接受人和接受时间，不重新蒸馏。
- **重复发布提醒**：同一版本在输出文件夹里有两份时，页面会提示。

AS 3500 实测：5 个标准、5 个现行版本、16 个旧版本、9 份修订单；7 份重复副本不再要求审核；2 个版本各发布了两次。

还没做：与官方目录核对版本状态（D-1 的外部证明）；从知识库撤下重复发布的那一份。

## 14. 阶段 C 进展（2026-11-22）

**标准答案从哪来**（方案评分）：
- 不靠人逐字校对：AS 3500 同一版本既有原生文字 PDF 又有扫描件（3500.1:2021、3500.3:2021），原生版就是扫描件的标准答案（9.6 分）。
- CI 里用 NCC 2025 第三卷的 4 页真实页面（CC BY 4.0，可以放进仓库），渲染、加损伤、识别，再和文字层对比（9.7 分，两者合用）。

**实测结果**（`docs/benchmarks/real-scans-2026-11-22.md`）：

| 扫描件由谁识别 | 词 | 数字 | 数字全对的页 |
|---|---|---|---|
| 我们的双引擎 OCR | 94% | 89–93% | 约 10% |
| 别人做的"可搜索"文字层 | 95–96% | 92–93% | — |

结论：扫描件离 99% 还很远，系统把它们留给人工审核是对的。

**修复**：
- **信任漏洞**：别人的 OCR 文字层以前被当作原生文字信任，3500.3:2021 的"可搜索版"因此被发布。现在每页是整页图片加文字的 PDF 一律按扫描件重新识别、校验（triage）。
- **CI 门槛**（`tests/test_eval_gate.py`）：
  - 自动接受的页必须数字全对、99% 以上的字读对；
  - 数字召回、字符召回低于基准就不能合并。
